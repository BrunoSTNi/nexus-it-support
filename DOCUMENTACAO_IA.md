Documentação de Uso da IA (NEXUS - Intelligent IT Support)Esta documentação registra a orquestração do desenvolvimento, o uso do agente de Inteligência Artificial (Gemini) e as decisões de Engenharia de Software aplicadas no projeto NEXUS, em conformidade com as diretrizes da disciplina.Tabela de Interações e Resolução de ProblemasProblema / RequisitoPrompts UtilizadosRefinamento (Iterações)Decisão de Engenharia1. Concepção e Arquitetura do Projeto (Documento de Visão)"Você é um Arquiteto de Software Sênior... O NEXUS é uma plataforma web inteligente de suporte de TI... Primeira etapa: NÃO comece programando. Primeiro produza: Documento de Visão..."A IA gerou o documento estruturado em Markdown. Solicitamos em seguida: "transforme essa documentação em um pdf e um docx bem estruturado". A IA forneceu o PDF gerado via script e o .md adaptado para importação direta no Word.Adotamos uma Arquitetura Modular baseada em DDD simplificado (separação física por domínios como /users, /tickets). A decisão garante que a aplicação possa crescer sem virar um monólito engessado. A IA atuou como consultora de arquitetura para validar as restrições do MVP.2. Setup de Infraestrutura (Boilerplate Node + Express + Typescript)"vamos começar o projeto" (após o contexto arquitetural já ter sido alimentado na sessão).Erro 1 (PowerShell): O terminal corrompeu o package.json (EJSONPARSE) por colar múltiplos comandos simultâneos. Correção: A IA instruiu a deleção do arquivo e a execução dos comandos npm init -y e npm install um a um.Erro 2 (Prisma): Falha ao executar comandos de migração devido à estrutura de pastas incorreta. Correção: Limpeza do cache do NPM (npm cache clean --force) e inicialização limpa do Prisma dentro da pasta /backend.Separação rigorosa das camadas de configuração (server.ts, prisma.ts) e isolamento do backend em sua própria sub-pasta. O TypeScript foi configurado com tipagem estrita para evitar erros em tempo de execução, adequando-se às boas práticas de Engenharia de Software.3. Orquestração do Banco de Dados via Docker e WSLExecução do docker-compose up -d para provisionar o PostgreSQL 15.Erro 1 (WSL): O Docker falhou com erro 500 (dockerDesktopLinuxEngine). Correção: A IA diagnosticou travamento no WSL e instruiu o reinício (wsl --shutdown).Erro 2 (Virtualização): Virtual Machine Platform is not enabled. Correção: Execução do comando Enable-WindowsOptionalFeature via PowerShell Admin e reinicialização física da máquina.O uso do Docker Compose foi mantido como obrigatório para garantir paridade de ambiente entre os membros do grupo. Resolvemos os gargalos de virtualização do Windows para assegurar que a entrega final rode perfeitamente na apresentação.4. Conflito de Versões do Prisma ORM e Conexão de BancoExecução da migração do banco (npx prisma migrate dev --name init).Erro 1 (Prisma v8): A versão mais recente do Prisma (v8) exigiu passos complexos não documentados (contract emit). Correção: Realizamos o downgrade para o Prisma v5 (npm i -D prisma@5), que possui fluxo mais adequado para o MVP.Erro 2 (Porta 5432): Erro P1000 Authentication failed. O volume Docker anterior havia "viciado" as credenciais na porta padrão. Correção: Alteramos o docker-compose.yml e o .env para expor a porta 5433, criando um banco 100% limpo.Decisão Crítica: Fazer o downgrade do Prisma para a versão 5 para priorizar a produtividade e estabilidade do MVP. Além disso, a troca de porta (5433) foi uma decisão defensiva para evitar conflitos com serviços locais pré-existentes nas máquinas do grupo.5. Criação do Módulo de Autenticação (JWT + Bcrypt)Requisito implícito após o sucesso da infraestrutura: criar sistema de registro de usuários e login com geração de token JWT.O código funcionou de primeira. A IA forneceu scripts PowerShell (Invoke-RestMethod) para testar o cadastro e o login diretamente do terminal, validando a geração do JWT com sucesso.Adotamos o padrão Controller-Service. O AuthService lida exclusivamente com a regra de negócio (hash de senhas com bcrypt e assinatura de tokens jsonwebtoken), enquanto o AuthController lida apenas com requisição/resposta HTTP (Express).
