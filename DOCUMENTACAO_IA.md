### Tabela de Uso da IA

| Problema / Requisito | Prompts Utilizados | Refinamento (Iterações) | Decisão de Engenharia |
| :--- | :--- | :--- | :--- |
| **Criação do Banco de Dados e ORM**<br><br>Precisávamos estruturar as tabelas (Users, Tickets, Categories) no PostgreSQL usando Prisma. | *"Gere o arquivo `schema.prisma` configurado para PostgreSQL. Crie os modelos User, Ticket e Category com seus devidos relacionamentos e chaves estrangeiras."* | **Erro de Tipagem e Cache:** O código gerado estava correto, mas ao tentar usar `prisma.category.findMany()`, o TypeScript acusava erro de *"Property 'category' does not exist"*. <br><br>**Correção:** Perguntamos à IA sobre o erro. Ela orientou a rodar `npx prisma generate` e recarregar o VS Code. Tivemos um erro de `EPERM` (arquivo trancado no Windows). A IA sugeriu rodar `taskkill /F /IM node.exe` antes de gerar novamente. Funcionou. | **Aprovado.** Optamos por manter o Prisma pela sua forte tipagem de dados. A decisão de matar o processo Node validou a compreensão de como o Windows gerencia locks de arquivos em tempo de desenvolvimento. |
| **Middleware de Autenticação (JWT)**<br><br>Criar a barreira de segurança garantindo que apenas usuários logados acessem a API. | *"Crie um middleware no Express chamado `ensureAuthenticated` que leia o token JWT do cabeçalho `authorization`, valide-o e bloqueie requisições não autorizadas."* | **Erro de Compilação TS:** A IA gerou a linha: `const [, token] = req.headers.authorization.split(' ');`. O TypeScript bloqueou a compilação afirmando que o tipo `string \| string[]` não possui a função `split`. <br><br>**Correção:** Pedimos à IA para corrigir o erro de tipagem. Ela ajustou para forçar a leitura como string: `(req.headers.authorization as string).split(' ')`. | **Aprovado.** A decisão de usar `as string` (Type Assertion) foi aceita pois sabemos que, no nosso ecossistema, o client (React) sempre enviará esse header como uma string única, mantendo o código seguro e o compilador satisfeito. |
| **Integração com IA (Classificador de Chamados)**<br><br>Criar uma rota que analisa a descrição do usuário e sugere categoria e prioridade do chamado estruturadas em JSON. | *"Atue como Engenheiro Backend. Crie um service `AIService` usando o SDK `@google/generative-ai`. Envie a 'descrição' do usuário e force o Gemini a devolver um JSON com category, priority, summary e keywords."* | **Erros 404 e 503:** A IA sugeriu o modelo `gemini-1.5-flash`, mas a API retornou erro 404. Iteramos com a IA pedindo alternativas. Fomos direcionados ao `gemini-3.8-flash`. Em seguida, recebemos erro 503 (Servidor sobrecarregado).<br><br>**Correção Arquitetural:** Pedimos à IA para implementar um sistema de "Fallback" (Plano B). Adicionamos um bloco `try/catch` que, em caso de falha da API externa, retorna um JSON estático de "Suporte Geral" e prioridade "LOW". | **Aprovado (Alta Resiliência).** Decidimos aprovar essa abordagem arquitetural porque previne que o servidor quebre (crash) por indisponibilidade de terceiros. Mantém a aplicação altamente disponível. |
| **Segurança do Repositório (Erro no GitHub Push)**<br><br>Evitar o vazamento da Chave de API do Gemini no GitHub. | *"O GitHub bloqueou meu `git push` com o erro: 'GH013: Push cannot contain secrets'. Como resolvo sem perder os meus commits?"* | **Falha Humana Corrigida:** Havíamos "comitado" o arquivo `.env` por acidente. A IA nos orientou a usar `git rm --cached backend/.env`, adicionar o arquivo no `.gitignore` e reescrever a árvore do git com `git commit --amend --no-edit`. | **Aprovado.** Adotamos a prática rigorosa de DevSecOps recomendada pela IA. Garantimos que variáveis de ambiente sensíveis rodem apenas localmente e nunca sejam expostas no controle de versão. |
