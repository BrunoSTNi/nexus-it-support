### Tabela de Uso da IA

| Problema / Requisito | Prompts Utilizados | Refinamento (Iterações) | Decisão de Engenharia |
| :--- | :--- | :--- | :--- |
| **Criação do Banco de Dados e ORM**<br><br>Precisávamos estruturar as tabelas (Users, Tickets, Categories) no PostgreSQL usando Prisma. | *"Gere o arquivo `schema.prisma` configurado para PostgreSQL. Crie os modelos User, Ticket e Category com seus devidos relacionamentos e chaves estrangeiras."* | **Erro de Tipagem e Cache:** O código gerado estava correto, mas ao tentar usar `prisma.category.findMany()`, o TypeScript acusava erro de *"Property 'category' does not exist"*. <br><br>**Correção:** Perguntamos à IA sobre o erro. Ela orientou a rodar `npx prisma generate` e recarregar o VS Code. Tivemos um erro de `EPERM` (arquivo trancado no Windows). A IA sugeriu rodar `taskkill /F /IM node.exe` antes de gerar novamente. Funcionou. | **Aprovado.** Optamos por manter o Prisma pela sua forte tipagem de dados. A decisão de matar o processo Node validou a compreensão de como o Windows gerencia locks de arquivos em tempo de desenvolvimento. |
| **Middleware de Autenticação (JWT)**<br><br>Criar a barreira de segurança garantindo que apenas usuários logados acessem a API. | *"Crie um middleware no Express chamado `ensureAuthenticated` que leia o token JWT do cabeçalho `authorization`, valide-o e bloqueie requisições não autorizadas."* | **Erro de Compilação TS:** A IA gerou a linha: `const [, token] = req.headers.authorization.split(' ');`. O TypeScript bloqueou a compilação afirmando que o tipo `string \| string[]` não possui a função `split`. <br><br>**Correção:** Pedimos à IA para corrigir o erro de tipagem. Ela ajustou para forçar a leitura como string: `(req.headers.authorization as string).split(' ')`. | **Aprovado.** A decisão de usar `as string` (Type Assertion) foi aceita pois sabemos que, no nosso ecossistema, o client (React) sempre enviará esse header como uma string única, mantendo o código seguro e o compilador satisfeito. |
| **Integração com IA (Classificador de Chamados)**<br><br>Criar uma rota que analisa a descrição do usuário e sugere categoria e prioridade do chamado estruturadas em JSON. | *"Atue como Engenheiro Backend. Crie um service `AIService` usando o SDK `@google/generative-ai`. Envie a 'descrição' do usuário e force o Gemini a devolver um JSON com category, priority, summary e keywords."* | **Erros 404 e 503:** A IA sugeriu o modelo `gemini-1.5-flash`, mas a API retornou erro 404. Iteramos com a IA pedindo alternativas. Fomos direcionados ao `gemini-3.8-flash`. Em seguida, recebemos erro 503 (Servidor sobrecarregado).<br><br>**Correção Arquitetural:** Pedimos à IA para implementar um sistema de "Fallback" em cascata com múltiplos modelos (`gemini-1.5-flash`, `gemini-1.5-pro`). Adicionamos um bloco `try/catch` que, em caso de falha da API externa, retorna um JSON estático de fallback. | **Aprovado (Alta Resiliência).** Decidimos aprovar essa abordagem arquitetural porque previne que o servidor quebre (crash) por indisponibilidade de terceiros, garantindo alta disponibilidade ao usuário. |
| **Segurança do Repositório (Erro no GitHub Push)**<br><br>Evitar o vazamento da Chave de API do Gemini no GitHub. | *"O GitHub bloqueou meu `git push` com o erro: 'GH013: Push cannot contain secrets'. Como resolvo sem perder os meus commits?"* | **Falha Humana Corrigida:** Havíamos "comitado" o arquivo `.env` por acidente. A IA nos orientou a usar `git rm --cached backend/.env`, adicionar o arquivo no `.gitignore` e reescrever a árvore do git com `git commit --amend --no-edit`. | **Aprovado.** Adotamos a prática rigorosa de DevSecOps recomendada pela IA. Garantimos que variáveis de ambiente sensíveis rodem apenas localmente e nunca sejam expostas no controle de versão. |
| **Integração Frontend e Backend (Tratamento de Autenticação e Erros)**<br><br>Corrigir o erro *"Usuário não autenticado"* ao criar chamados e unificar contratos de dados. | *"Estou recebendo 'Usuário não autenticado' ao enviar chamados e o TypeScript reclama de propriedades no Request do Express e em req.params."* | **Diagnóstico e Correção:** Identificamos que o middleware gravava dados em `req.user`, mas o controller lia `req.userId`. A IA ajudou a unificar criando uma extensão global de tipos para o Express (`express.d.ts`) definindo `req.userId` explicitamente. Além disso, corrigimos a extração de parâmetros de rota (`req.params.id as string`) e garantimos que o helper `httpPost` no frontend anexasse o `Authorization: Bearer <token>` corretamente no localStorage. | **Aprovado.** A tipagem de ponta a ponta eliminou falhas de contrato entre o React e o Express, garantindo fluxo seguro de persistência via Prisma. |
| **Implementação de Layout e Estilização (Design System e Telas)**<br><br>Integrar o protótipo visual refinado (login com duas colunas e dashboard) ao código funcional. | *"Como integrar o layout visual refinado (órbitas animadas, paleta de cores moderna e design responsivo) ao nosso código React/Tailwind mantendo a funcionalidade?"* | **Ajustes de Estilização:** A IA auxiliou na reestruturação do arquivo CSS global, removendo dependências incompatíveis (`tw-animate-css`), organizando os imports de fontes e mapeando os componentes de login e dashboard para lidar com os estados de carregamento, validações e feedback visual. | **Aprovado.** Elevou a experiência do usuário (UX/UI) com uma interface moderna, polida e perfeitamente integrada aos requisitos acadêmicos e profissionais do projeto. |
